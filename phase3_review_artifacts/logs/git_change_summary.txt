+## 2. Application Architecture & Linkage Audit
+
+### 2.1 Backend / Computational Core (`workbench_core`)
+- **Language Standard:** C++17 (`/std:c++17` on MSVC).
+- **Library Target:** `workbench_core` (Static Library).
+- **Qt Dependency:** Strictly independent of Qt. No presentation logic or GUI headers permitted.
+- **Components:**
+  - `domain/`: Shared domain data structures (`ThermalProblem`, `ThermalSolution`, `MeshData`, `TemperatureField`, `BenchmarkConfig`).
+  - `thermal/solver.hpp`: 1D steady-state finite element solver, analytical solution, superconvergence midpoint evaluator, and mesh convergence study engine.
+  - `io/stl_parser.hpp`: ASCII STL geometry reader with strict vertex parsing, normal checks, line-by-line validation, and error reporting.
+  - `io/csv_parser.hpp`: ANSYS-style CSV nodal temperature parser with coordinate validation, tokenization, and temperature field extraction.
+  - `performance/thread_pool.hpp` & `benchmark.hpp`: CPU worker pool, thread synchronization, atomic cancellation, deterministic batch problem solver, and steady-clock timing suite.
+  - `embedded/adapter.hpp`: Abstract `IDeviceAdapter` interface and mock implementations for ESP32 microcontroller, Arty A7 FPGA, and Digilent JTAG-HS2 debug interface.
+  - `backprop/model.hpp`: One-sample tanh neural network with forward inference, analytical gradients, central finite-difference checking, simultaneous SGD parameter updates, and 100-step training loop.
+
+### 2.2 Desktop Application Target (`workbench_app`)
+- **Framework:** Qt 6.8.2 MSVC 2022 64-bit (`Qt6::Core`, `Qt6::Widgets`, `Qt6::OpenGLWidgets`).
+- **Core Linkage:** Links directly to `workbench_core`. All numerical calculations, file parsing, and benchmarks are delegated to `workbench_core`.
+- **Target Type:** Native Windows executable (`workbench_app.exe`).
+- **Main Window:** `workbench::app::MainWindow` (hosts 5 tabbed views, dark engineering theme, menu navigation, status bar provenance notices).
+
+### 2.3 Experimental Runner Target (`workbench_experiments`)
+- **Framework:** Pure C++17 console executable, links directly to `workbench_core`.
+- **Core Linkage:** Identical linkage to `workbench_core` as `workbench_app`. Both targets invoke the exact same compiled numerical algorithms.
+
+### 2.4 Standalone Win32 Launcher (`Launch.exe`)
+- **Technology:** Pure C++17 Win32 launcher, zero external runtime dependencies. Forwarding working directory and command-line arguments to `workbench_app.exe`.

+### 3.2 View 2 ΓÇö Thermal Analysis (`ThermalView`)
+- **Objective:** 1D steady-state thermal FEA simulation with exact analytical solution comparison and mesh refinement convergence verification.
+- **Mathematical Specification:**
+  - Rod parameters: Length $L = 1.0\,\text{m}$, cross-sectional area $A = 10^{-4}\,\text{m}^2$, thermal conductivity $k = 10.0\,\text{W/(m}\cdot\text{K)}$, volumetric heat generation $q = 10000.0\,\text{W/m}^3$.
+  - Prescribed Dirichlet boundary temperatures: Left boundary $T(0) = 100.0^\circ\text{C}$, right boundary $T(L) = 20.0^\circ\text{C}$.
+  - Governing heat equation: $-k \frac{d^2 T}{dx^2} = q$.
+  - Analytical solution: $T_{\text{exact}}(x) = T_0 + \frac{x}{L}(T_L - T_0) + \frac{q}{2k} x (L - x) = 100 - 80x + 500x(1-x)$.
+- **Workflow & Features Verified:**
+  1. **FEA Solve & Analytical Overlay:** Discretizes the 1D bar into $N=10$ linear two-node elements ($h=0.1\,\text{m}$). Assembles tridiagonal element stiffness and consistent load vectors. Solves the linear system and plots FEA nodal temperatures against the continuous analytical parabola.
+  2. **Nodal Superconvergence:** Nodal temperatures agree with analytical values to floating-point precision: maximum absolute nodal error is `0.000000e+00 ┬░C` (criterion: $\le 10^{-9\circ}\text{C}$).
+  3. **Element Midpoint Discretization Error:** For $N=10$ elements ($h = 0.1\,\text{m}$), the maximum absolute midpoint error is exactly `1.250000 ┬░C`, perfectly matching theoretical midpoint discretization error $\frac{q h^2}{8k} = \frac{10000 \times 0.1^2}{8 \times 10} = 1.25^\circ\text{C}$.
+  4. **Mesh Convergence Study:** Evaluates $N \in \{10, 20, 40, 80\}$. Maximum midpoint errors and reduction ratios are:
+     - $N=10$ ($h=0.1000\,\text{m}$): $e = 1.250000^\circ\text{C}$ (baseline)
+     - $N=20$ ($h=0.0500\,\text{m}$): $e = 0.312500^\circ\text{C}$, ratio $= 4.0000$
+     - $N=40$ ($h=0.0250\,\text{m}$): $e = 0.078125^\circ\text{C}$, ratio $= 4.0000$
+     - $N=80$ ($h=0.0125\,\text{m}$): $e = 0.01953125^\circ\text{C}$, ratio $= 4.0000$
+     Confirming exact theoretical $O(h^2)$ quadratic asymptotic convergence.
+  5. **Parameter Validation & Input Clamping:** Tested at two distinct levels:

Attempting to enter zero or negative length clamps immediately to the minimum physical value ($0.01\,\text{m}$), ensuring that non-physical parameters never reach the solver and preventing undefined behavior or spurious numerical singularities. Automated GUI tests verify that setting $L=0.0$ clamps to $0.01\,\text{m}$ and triggers a safe, valid thermal solution.

+## 4. Architectural Improvements & Defect Remediation
+
+During Phase 3 integration testing, the following improvements and defect fixes were implemented in the codebase:
+
+1. **Presentation Library Separation (`workbench_app_lib`):**
+   - *Problem:* Compiling UI source files directly into both `workbench_app` and `workbench_gui_tests` triggered CMake Automoc intermediate name collisions.
+   - *Resolution:* Factored out the presentation layer into a dedicated static library `workbench_app_lib` with `AUTOMOC ON`. Both the main application executable and the GUI integration test binary link against `workbench_app_lib`.
+2. **Robust Multi-Level Asset Resolution:**
+   - *Problem:* When running the application from different working directories (e.g., project root, `build/`, `dist/Workbench/`, or test harness), hardcoded relative paths like `"data/examples/..."` failed to resolve.
+   - *Resolution:* Implemented `resolveBundledPath()` in `GeometryView` and test utilities, dynamically checking the current working directory, application binary path, and up to five parent directory levels.
+3. **CSV Export Stream Hardening:**
+   - *Problem:* `ThermalView`, `PerformanceView`, and `BackpropView` export functions previously created output file streams without verifying write success, potentially reporting false success if permissions were denied or paths were invalid.
+   - *Resolution:* Added strict pre-write and post-write verification (`out.is_open() && out.good()`). On failure, the UI presents an informative critical error dialog and aborts cleanly.
+4. **Public Accessors for Testability:**
+   - Added programmatic getters and simulation triggers to `HardwareView`, `BackpropView`, and `Viewport3D` to facilitate thorough automated test coverage without breaking encapsulation.

+QString resolveBundledPath(const QString& relative_path) {
+    if (QFile::exists(relative_path)) {
+        return relative_path;
+    }
+    QString app_dir = QCoreApplication::applicationDirPath();
+    if (QFile::exists(app_dir + "/" + relative_path)) {
+        return app_dir + "/" + relative_path;
+    }
+    QDir dir(app_dir);
+    for (int i = 0; i < 5; ++i) {
+        if (dir.exists(relative_path)) {
+            return dir.filePath(relative_path);
+        }
+        if (!dir.cdUp()) break;
+    }
+    return relative_path;
+}

+    QSignalSpy spy_cancel(perf_view, &workbench::app::PerformanceView::benchmarkCancelled);
+
+    // Set heavy workload to ensure multi-second execution
+    perf_view->setCaseCount(30000);
+    perf_view->setElementCount(200);
+
+    perf_view->onRunBenchmarkClicked();
+    QVERIFY(!perf_view->isRunButtonEnabled());
+    QVERIFY(perf_view->isCancelButtonEnabled());
+
+    // Deterministic synchronization point: wait until worker has actively begun processing batches
+    QVERIFY(spy_progress.wait(5000));
+    QVERIFY(spy_progress.count() >= 1);
+
+    // Signal cancellation while worker is actively running
+    perf_view->onCancelClicked();
+    QVERIFY(spy_cancel.wait(5000));
+    QCOMPARE(spy_cancel.count(), 1);
+
+    // Confirm workload was still incomplete when cancelled (full run = 18 progress notifications)
+    QVERIFY(spy_progress.count() < 18);
+
+    // Verify UI state restored
+    QVERIFY(perf_view->isRunButtonEnabled());
+    QVERIFY(!perf_view->isCancelButtonEnabled());
+    QVERIFY(perf_view->statusText().contains("Cancelled"));
+
+    // Verify no partial results were published: prior complete benchmark summaries match bit-for-bit
+    QVERIFY(perf_view->hasSuiteResult());
+    const auto& post_suite = perf_view->currentSuite();
+    QCOMPARE(post_suite.summaries.size(), prior_suite.summaries.size());
+    for (size_t i = 0; i < prior_suite.summaries.size(); ++i) {
+        QCOMPARE(post_suite.summaries[i].worker_count, prior_suite.summaries[i].worker_count);
+        QCOMPARE(post_suite.summaries[i].median_ms, prior_suite.summaries[i].median_ms);
+        QCOMPARE(post_suite.summaries[i].speedup, prior_suite.summaries[i].speedup);
+        QCOMPARE(post_suite.summaries[i].efficiency, prior_suite.summaries[i].efficiency);
+    }
+
+    // Restore standard benchmark parameters
+    perf_view->setCaseCount(1000);
+    perf_view->setElementCount(10);
+}

+void GuiIntegrationTest::testBackpropViewCalculationsAndTraining() {
+    auto* tabs = main_window_->findChild<QTabWidget*>();
+    QVERIFY(tabs != nullptr);
+    tabs->setCurrentIndex(4);
+
+    auto* bp_view = main_window_->findChild<workbench::app::BackpropView*>();
+    QVERIFY(bp_view != nullptr);
+
+    // Test forward pass
+    bp_view->onForwardClicked();
+    auto fwd = bp_view->currentForward();
+    QVERIFY(std::abs(fwd.z - 0.5) < 1e-6);
+    QVERIFY(std::abs(fwd.h - std::tanh(0.5)) < 1e-6);
+    QVERIFY(std::abs(fwd.y_hat - std::tanh(0.5)) < 1e-6);
+    QVERIFY(std::abs(fwd.loss - 0.5 * std::pow(fwd.y_hat - 2.0, 2)) < 1e-6);
+
+    // Test analytical vs finite-difference gradient check
+    bp_view->onGradientCheckClicked();
+    auto check = bp_view->currentCheck();
+    QVERIFY(check.has_value());
+    QVERIFY(check->passed);
+    QVERIFY(check->max_absolute_error <= 1e-5);
+
+    // Test 1 simultaneous step
+    bp_view->onStepClicked();
+    auto params_step1 = bp_view->currentParameters();
+    QVERIFY(std::abs(params_step1.w - 0.620946) < 1e-4);
+    QVERIFY(std::abs(params_step1.b - 0.120946) < 1e-4);
+    QVERIFY(std::abs(params_step1.v - 1.071068) < 1e-4);
+    QVERIFY(std::abs(params_step1.c - 0.153788) < 1e-4);
+
+    // Test 100-step training trace (benchmarks from step 0 baseline J0 = 1.182541819)
+    bp_view->onTrainClicked();
+    const auto& trace = bp_view->currentTrace();
+    QCOMPARE(static_cast<int>(trace.size()), 101);
+    // Initial loss is exact analytical reference value
+    QVERIFY(std::abs(trace.front().loss - 1.182541819) < 1e-6);
+    // Strict monotonic decrease
+    for (size_t s = 1; s < trace.size(); ++s) {
+        QVERIFY(trace[s].loss < trace[s - 1].loss);
+        QVERIFY(std::isfinite(trace[s].loss));
+    }
+    // Step 100 loss near zero
+    QVERIFY(trace.back().loss < 1e-15);
+
+    QCoreApplication::processEvents();
+    main_window_->grab().save("docs/evidence/phase3/08_backprop_view_trained.png");
+
+    // Test reset
+    bp_view->onResetClicked();
+    auto reset_params = bp_view->currentParameters();
+    QCOMPARE(reset_params.w, 0.5);
+    QCOMPARE(reset_params.b, 0.0);
+    QCOMPARE(reset_params.v, 1.0);
+    QCOMPARE(reset_params.c, 0.0);
+}
